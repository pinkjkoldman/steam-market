# CR-004 + CR-005 G4 测试计划

## 1. 目标与范围

本轮验证启动登录/游客模式、统一身份与权限、Steam 全市场概览、远端按需分页、缓存降级、迁移 0006、响应式 UI 和安全边界。既有行情、提醒、持仓、CSV、K 线、费用、交易、盘口和库存能力纳入全量回归。

不执行市场买卖、不自动遍历全市场、不主动制造 429、不采集或记录 Steam 凭据。真实密码和 Steam Guard 仅由用户在 Steam 官方 WebView2 页面输入。

## 2. 环境

- Windows 11，Qt 6.11.0，MinGW 13.1.0；
- Microsoft Edge WebView2 Runtime 151.0.4129.78；本地 SDK 目标版本 150.0.4078.44；
- SQLite 临时数据库；Steam 联网验证使用匿名、无 Cookie、单次 10 条请求；
- 原生 Windows 渲染，系统 150% DPI；逻辑视口 1040×680、1280×800、1920×1080。

## 3. 策略

| 层级 | 对象 | 方法 |
| --- | --- | --- |
| 单元/集成 | 11 个 Qt Test 测试类 | 强制重建、固定 fixture、临时 SQLite、假 WebView 宿主 |
| 运行时 | 完整桌面应用 | 强制重建、`--smoke-test`、三档截图 |
| 联网 | Steam 市场目录 | 单次匿名 GET，核对 HTTP/JSON/分页元数据 |
| 安全 | 会话、权限、网络、缓存、依赖 | 源码扫描、边界测试、签名/版本核对、官方公告适用性分析 |
| UAT | 真实 Steam 登录/Steam Guard/注销 | 用户在官方 WebView2 页面手工执行，Codex 不接触凭据 |

## 4. 重点风险

1. 游客、公开库存、认证中、认证和过期状态混淆；
2. 登录前残留 Cookie、注销不完整、SteamID 信号不一致；
3. 网页端点结构变化、超大响应、429、重定向或非 JSON；
4. 登录 Cookie 被目录请求复用，或后台自动分页形成全量抓取；
5. 缓存污染、旧响应覆盖新查询、迁移破坏旧库；
6. 小窗口、高 DPI、键盘和文字对比度不可用。

## 5. 准出标准

- 自动化 Must 测试 100% 执行，通过率不低于 95%；
- 三档运行时冒烟全部退出码 0；
- 无开放高危产品缺陷或高危安全漏洞；
- 真实账户 UAT 完成，日志、数据库和截图不含 Cookie、密码或 Steam Guard；
- G4 报告获用户批准后，才可进入 G5。
