# CR-006：真实市场数据走势图与行情可信度完善

- 提出人：用户
- 日期：2026-08-17
- 状态：G1 需求待审批
- 规模：小型跨层迭代，沿用项目简化流程
- 影响阶段：需求、架构/API/数据/UI、安全、开发、联网测试与发布说明

## 1. 背景

项目已经具备 Steam 市场目录、单品概览、`pricehistory` 历史读取、SQLite 缓存、折线图和日 K 聚合的基础链路；确定性演示行情仅在 `--smoke-test` 中写入。

当前仍不能把界面称为“可靠的真实数据走势”：

1. 登录态历史接口失败、空响应和解析失败没有形成明确的数据状态，用户难以区分实时、缓存和不可用；
2. 登录成功后虽会把 Steam Cookie 导入网络会话，但详情页没有完整的“需要登录 → 登录 → 自动重试”闭环；
3. 价格折线与销量柱共用不匹配的时间轴实现，时间位置和销量表达不可靠；
4. “分时”只是最近 24 小时的官方历史点，并非逐分钟或逐笔成交；日 K 也是对官方历史点的本地聚合，当前文案容易造成过度承诺；
5. 现有自动测试使用 fixture/临时数据库，尚未提供可复核的真实 Steam 联网验收证据。

## 2. 目标与成功指标

### 2.1 目标

- 用户主动打开一个 Steam 市场物品时，应用可获取、缓存并绘制该物品的 Steam 官方市场历史价格与成交量走势；
- 用户始终能知道数据来源、币种、采集时间、登录要求、缓存/实时状态和失败原因；
- 不使用随机数据、演示数据或本地模拟值冒充真实行情；
- 图表语义与 Steam 实际提供的数据粒度一致。

### 2.2 成功指标

1. 已登录且 Steam 返回至少 2 个有效历史点时，详情页在 5 秒目标时间内绘制真实价格走势；
2. 每次渲染均显示来源、币种、最后更新时间、点数和“在线/缓存”状态；
3. 未登录、429/403、网络失败、响应结构变化和真实空数据具有不同提示与恢复动作；
4. 普通启动路径和用户数据库中不会写入 `smoke fixture` 或正弦演示行情；
5. 自动化测试覆盖解析、时间排序、去重、缓存降级、坐标轴与数据状态；发布前完成至少 1 个真实 CS2 市场物品的人工联网验收。

## 3. 用户与核心场景

- 主要用户：需要观察 Steam 饰品价格变化的个人用户；
- 主流程：浏览/搜索物品 → 打开详情 → 读取真实历史 → 切换周期 → 查看价格/成交量 → 识别来源与新鲜度；
- 恢复流程：未登录或会话失效 → 页内登录 → 成功后自动重试一次 → 保留当前物品和周期；
- 离线流程：网络失败 → 展示可追溯缓存 → 标明缓存时间 → 用户可手动重试。

### Could

- 自选列表显示最近真实历史的迷你走势；
- 导出当前物品历史为 CSV，并附来源与时间元数据；
- 对长期本地快照生成单独标记的“本地采样走势”。

### Won't

- 后台遍历全市场并逐个请求历史；
- 绕过登录、429、验证码或 Steam 访问控制；
- 把 publisher key、Cookie 或令牌嵌入程序或写入日志/SQLite；
- 引入未经授权的第三方历史源；
- 把 Steam 聚合历史点描述为逐笔成交或证券交易所级实时行情；
- 在本变更中实现自动交易或无人值守采集。

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 可信度 | 所有图表必须可追溯到来源、appid、物品、币种和采集时间；fixture 有显式测试标记 |
| 性能 | 有缓存时首屏目标 <300 ms；远端历史目标 <5 s；UI 请求期间不冻结 |
| 限流 | 单并发、沿用至少 1.5 秒间隔；尊重 429/403，不自动连续重试超过既定上限 |
| 安全 | 仅复用用户主动建立的内存 Steam 会话；日志、截图、数据库不得出现 Cookie/令牌 |
| 数据一致性 | 写入事务化；无效点不落库；相同维度与时间幂等；读取稳定排序 |
| 兼容性 | Windows 10/11、Qt 6.11、Qt Charts；游客和 WebView2 不可用时仍可查看缓存 |
| 可访问性 | 图表状态不只依赖颜色；关键数值可由文字读取；1040×680 与 125%/150% DPI 可用 |
| 可测试性 | 网络解析使用固定官方响应形态 fixture；真实联网测试与自动化 fixture 明确分离 |

## 6. 数据语义约束

- `Steam 历史点`：Steam Community Market 单品页面/会话返回的时间、价格、数量三元组；
- `最近 24 小时`：仅筛选最近 24 小时内已有历史点，不保证每分钟一个点；
- `日 K`：按自然日对历史点聚合得到的 open/high/low/close/volume，仅作为趋势辅助；
- `在线`：本次用户动作获得并校验的新响应；
- `缓存`：此前有效响应或本地采样，必须显示最后采集时间；
- `真实空数据`：Steam 明确成功但没有有效点；不得与认证失败或解析失败合并。

## 7. 风险与假设

- Steam 社区市场网页端点不是面向普通桌面客户端承诺的稳定历史 API；字段、认证和限流可能变化；
- Steam 官方单品页确实提供价格图表，但程序化历史读取仍需以用户会话和实际响应为准；
- Steamworks 官方 `IEconMarketService` 是受限合作伙伴接口，publisher key 不能放在客户端，因此本项目继续使用用户主动访问的官方社区市场页面数据和本地缓存；
- 真实账户联网验收必须由用户主动完成 Steam 登录，测试过程不得要求用户提供密码、Cookie 或 Steam Guard 密钥。
