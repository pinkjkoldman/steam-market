# CR-004：启动登录与游客模式

## 背景

当前 Steam 官方登录入口只存在于“库存助手”内部。启动时无法立即理解账户能力；“未登录”“公开库存身份”和“已登录会话”又使用相近状态，导致权限边界与下一步操作不清楚。

## 目标与成功指标

1. 首次启动提供“登录 Steam”与“游客模式”两个清晰入口；
2. 游客无需账户即可使用公开行情、排行、规则、自选与本地模拟功能；
3. 私人库存或登录态行情等受限能力在操作点解释原因，并可一键发起官方登录；
4. 全局始终可见当前身份，并可在登录、游客和退出之间切换；
5. 应用不接收 Steam 密码，不要求粘贴 Cookie，不把普通设置用于保存登录 Cookie。

成功标准：新用户一次选择即可进入；受限操作不无解释失败；身份切换无需重启；现有游客可用功能保持可用。

## 身份状态定义

| 状态 | 含义 | 允许能力 |
| --- | --- | --- |
| 待选择 | 首次启动尚未选择模式 | 仅显示启动身份选择页 |
| 游客 | 无 Steam 登录会话 | 公开行情、排行、规则、自选、本地持仓/模拟、公开库存查询 |
| 公开库存身份 | 游客输入有效 SteamID64 | 游客能力 + 读取该公开库存；不代表账户已登录 |
| 已登录 | Steam 官方页面已建立有效会话 | 游客能力 + 私人库存、登录态历史/盘口及账户相关官方页面 |

## 功能清单（MoSCoW）

### Must

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| CR4-F1 | 启动身份选择 | 首次正常启动显示欢迎页，提供登录和游客；冒烟测试不阻塞 |
| CR4-F2 | 官方安全登录 | 打开 Steam 官方 WebView；应用不接收密码；成功后进入库存助手 |
| CR4-F3 | 游客模式 | 直接进入行情页，不强制注册或输入 SteamID |
| CR4-F4 | 全局账户状态 | 侧栏显示游客/公开库存/已登录，并提供登录、切换或退出入口 |
| CR4-F5 | 权限就地升级 | 受限能力显示原因及“登录 Steam”按钮 |
| CR4-F6 | 状态一致性 | 欢迎页、全局账户区与库存助手共用同一会话状态 |
| CR4-F7 | 安全退出 | 清除 WebView、网络 Cookie 与内存身份；保留本地数据 |

### Should

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| CR4-F8 | 记住启动选择 | 仅保存 guest 或 ask 偏好，不保存认证结果或 Cookie |
| CR4-F9 | 欢迎页价值说明 | 说明行情、提醒、库存助手及模式差异 |
| CR4-F10 | 公开库存延续 | SteamID64 查询继续可用，并明确不是登录账户 |

### Could

- 保存最近公开 SteamID64（用户显式选择）；
- 登录过期时保留页面并显示重新登录横幅；
- 设置页提供“启动时询问 / 直接游客模式”。

### Won't

- 自建 Steam 用户名/密码输入框；
- 保存密码、Steam Guard、恢复码、共享密钥；
- 在普通 SQLite 设置 JSON 中保存 Cookie 或令牌；
- 绕过库存隐私、市场限制和确认流程；
- 多账户 Cookie 同时在线管理。

## 非功能需求

| 类别 | 要求 |
| --- | --- |
| 安全 | 密码仅进入 Steam 官方页面；日志、数据库与截图不得包含 Cookie/令牌；退出清理两套 Cookie 容器 |
| 可用性 | 首次选择不超过一个页面；游客与登录入口同等可见；恢复路径不超过一次点击 |
| 一致性 | 身份状态由单一服务发布，页面不得自行推断是否登录 |
| 性能 | 欢迎页 300ms 内可交互；切换游客不发起网络请求 |
| 兼容性 | Windows 10/11、Qt 6.11；WebView2 不可用时游客仍可进入 |
| 可测试性 | 冒烟可绕过欢迎页；覆盖游客、登录成功/失败、退出和过期 |

## 关键假设与待设计项

- 默认推荐游客模式；登录是解锁私人能力，不是使用前置条件。
- 本次只记住启动选择，不自动恢复 Steam 登录 Cookie。
- DPAPI 安全恢复会话须在安全设计阶段单独评估并明确批准。

## 影响范围

架构、安全、UI/UX、设置模型、SteamSessionService、MainWindow、库存助手、冒烟与账户状态测试。

## UI 可用性需求（G1 基线）

### 启动欢迎页

- 欢迎页是身份与能力选择页，不是传统账号密码表单；不得出现应用自建的用户名、密码或验证码输入框。
- “游客模式”和“登录 Steam”采用并列模式卡片：标题、适用能力、限制说明和明确主动作均在首屏可见。
- 游客模式标记为“推荐”，但登录入口不得弱化为文字链接；两者视觉权重接近，避免诱导或强制登录。
- 登录卡片必须显示“通过 Steam 官方页面登录”“应用不接收或保存密码”。
- “下次自动使用所选模式”与模式选择分离，默认不勾选，避免用户无意跳过欢迎页。
- 欢迎页允许关闭时，关闭行为等同游客进入；不得让用户陷入无主界面的死路。

### 全局账户区

- 主侧栏底部固定显示账户卡片，并在所有一级页面保持位置稳定。
- 游客显示中性头像、游客标签和“登录 Steam”；公开库存显示 SteamID64 尾号及“仅公开数据”；已登录显示名称、SteamID64 尾号和安全状态。
- 已登录的“退出登录”属于低频危险操作，放入账户菜单并二次确认，不与主要导航并列。
- 状态改变时账户卡片、库存页和受限提示同步更新；不得出现侧栏已登录、页面仍显示游客的矛盾状态。

### 受限能力与恢复

- 游客进入库存助手仍可看到公开库存入口；私人库存区使用页内登录引导，不立即弹出模态登录框。
- 登录中显示可取消的明确进度状态；登录失败、WebView2 缺失、网络错误和会话过期使用不同文案与恢复动作。
- 登录成功后优先回到用户发起登录前的任务；没有来源任务时进入库存助手。
- 会话过期采用非阻塞横幅，保留当前页面和本地数据，不清空用户筛选或草稿。

## 美术与品牌需求（G1 基线）

### 视觉定位

美术关键词定为：**专业市场终端 × Steam 社区氛围 × 克制的游戏质感**。

- 以深海蓝黑为基础，冷蓝作为交互强调，青绿色仅用于可信/已登录/成功状态；涨跌色继续服从用户设置。
- 界面优先服务长时间数据阅读，装饰不得压过价格、数量、状态和任务操作。
- 品牌应形成 Steam Market Terminal 自身识别，不直接复制 Steam 客户端版式、商标或官方登录页视觉。

### 关键美术资产

| 优先级 | 资产 | G2 设计目标 |
| --- | --- | --- |
| Must | 应用标识与 SM 品牌标记 | 小尺寸清晰，适合标题栏、侧栏和 Windows 图标 |
| Must | 统一线性图标集 | 导航、账户、搜索、提醒、库存、设置风格一致，不混用 Emoji |
| Must | 欢迎页背景视觉 | 抽象市场曲线、饰品卡片或库存网格，低对比度且不干扰文字 |
| Must | 身份状态图形 | 游客、公开库存、已登录、过期均有图标 + 文案，不只依赖颜色 |
| Should | 空状态图形 | 无搜索结果、库存为空、受限功能、登录失败使用同一视觉家族 |
| Could | 启动画面与品牌动效 | 仅在不拖慢启动和不阻塞操作时采用 |

### 组件视觉层级

- 重要价格与汇总数字使用等宽数字或等宽特性，保证列对齐和跳变稳定。
- 主按钮每个任务区最多一个；次要、链接、危险操作必须有明确层级。
- 卡片与面板使用轻边框和有限层级，不堆叠重阴影、大面积毛玻璃或高饱和渐变。
- 图标不得承担唯一语义；未知图标必须配文字或工具提示。
- 动效时长建议 120～220ms，限于淡入、状态切换和轻量位移；尊重减少动态效果设置。

### 禁止风格

- 不采用传统网页登录框、启动器广告轮播、赌场式高饱和金色或霓虹；
- 不使用无意义 3D 装饰、大面积动态背景或持续闪烁行情；
- 不混用 Emoji、文本箭头、多套图标和多个圆角体系；
- 不用纯颜色区分游客、登录、涨跌或错误状态。

## 响应式与可访问性要求

| 场景 | 验收要求 |
| --- | --- |
| 1040×680 | 欢迎页两个入口、主动作和安全说明无需滚动即可看到；侧栏账户卡片可达 |
| 1280×800 | 默认密度下无文字截断，主要表格与任务区保持完整层级 |
| 1680×1080 / 2K | 内容不被无限拉宽；关键区域使用合理最大宽度和留白 |
| 125% / 150% DPI | 文案、图标和按钮不重叠；点击目标保持至少约 36px 高 |
| 键盘 | Tab 顺序先模式卡片后记住选项；Enter 激活当前主操作；Esc 不会误退出应用 |
| 对比度 | 正文目标 WCAG AA 4.5:1；大字和非文本控件边界至少 3:1 |
