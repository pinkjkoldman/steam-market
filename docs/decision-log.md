> 记录项目全程的关键技术与业务决策。架构决策记录（ADR）存放在 docs/design/adr/。

### D-001：Qt Widgets 桌面单机架构
- 日期/阶段：2026-08-01 / 阶段 2
- 决策者：系统架构师（用户确认 Qt 方向）
- 背景：行情类桌面小工具，需兼顾表格性能与开发效率
- 备选方案：Qt Quick/QML；本地后端+Electron
- 结论：Qt Widgets 单进程 + 服务层 + SQLite（ADR-001）
- 理由：表格/图表场景成熟、单机部署最简、本机工具链现成
- 影响：单机单用户，无云同步
- 关联文档：docs/design/adr/ADR-001-qt-desktop-architecture.md

### D-002：SQLite 本地存储
- 日期/阶段：2026-08-01 / 阶段 2
- 决策者：系统架构师 + 数据库工程师
- 备选方案：JSON 文件；客户端-服务器数据库
- 结论：SQLite（WAL、外键、版本化迁移）
- 理由：零部署、索引/事务完备，适合高频行情快照
- 影响：数据位于 %APPDATA%，需备份与保留策略
- 关联文档：docs/design/database-design.md

### D-003：第三方比价采用可插拔数据源 + CSV 兜底

### D-008：费用模型按卖家到手价计算
- 日期/阶段：2026-08-01 / v2 开发
- 决策者：后端工程师
- 背景：Steam 手续费（平台 5% + 游戏 10%）按卖家到手价计算，买卖双向口径不同
- 结论：卖出输入到手价→费用=费率×价、买家付=价×(1+费率)；买入输入买家支付→反推到手
- 理由：与 Steam 实际结算口径一致（示例：买家付 34.50，卖家得 30.00）
- 影响：费用计算器与模拟交易统一使用该模型；费率可配置

### D-012：CR-004 游客优先与认证不持久化
- 日期/阶段：2026-08-13 / CR-004 需求
- 决策者：用户（提出）+ 总设计师
- 背景：登录入口隐藏在库存助手，未登录与公开库存身份边界不清。
- 结论：首次启动提供游客与 Steam 官方登录；游客可使用公开/本地功能；公开 SteamID 不视为认证；本次不跨重启保存 Steam Cookie。
- 理由：降低首次使用门槛，同时控制本地凭据风险并保持 Steam 官方认证边界。
- 影响：需新增统一身份状态机、欢迎页、全局账户区、权限升级提示与安全测试。

### D-013：CR-004 UI 与美术基线
- 日期/阶段：2026-08-13 / CR-004 G1
- 决策者：用户（提出）+ 产品经理 + 总设计师
- 背景：账户入口除功能正确外，还需提升品牌识别、可信感和长时间使用可读性。
- 结论：视觉定位为“专业市场终端 × Steam 社区氛围 × 克制的游戏质感”；欢迎页采用登录/游客并列卡片；统一自有品牌、线性图标和身份状态视觉。
- 理由：兼顾 Steam 用户熟悉感与专业数据终端效率，避免传统登录框或游戏启动器式视觉干扰。
- 影响：G2 必须提供高保真、多状态、响应式、对比度和资产规范，G4 按截图与可访问性验收。

### D-014：CR-004 单一身份状态源与权限门

- 决策者：系统架构师 + 安全工程师 + 总设计师
- 背景：现有布尔状态无法区分游客、公开库存、认证中和会话失效，旧历史中还存在 AuthService 概念。

### D-015：CR-004 新鲜登录会话与零数据库迁移
- 日期/阶段：2026-08-13 / CR-004 G2
- 决策者：安全工程师 + 数据库工程师
- 背景：WebView2 用户数据目录可能在异常退出后保留 Cookie，而需求禁止跨重启自动恢复认证。
- 结论：每个进程首次登录导航前先清 WebView 与网络 Cookie，清理失败阻断登录；设置仅保存 `ask|guest`，无需 SQL schema 迁移。
- 理由：启动前清理覆盖异常退出场景，且设置无法伪造认证态。
- 影响：G3 需扩展 `IWebSessionHost` 的异步清理契约并补残留 Cookie 集成测试。
- 关联文档：docs/design/security-CR-004-account-entry.md、docs/design/database-design-CR-004-account-entry.md

### D-017：CR-005 Steam 全市场采用远端按需分页
- 日期/阶段：2026-08-13 / CR-005 G2 修订
- 决策者：用户（提出）+ 系统架构师 + 安全工程师 + 总设计师
- 背景：用户明确要求市场概览显示 Steam 全市场数据，而非本地关注/浏览标的池。
- 备选：启动全量镜像；合作伙伴 GetPopular；自建云采集；Steam 官方市场网页端点按需分页。
- 结论：市场概览和物品浏览以 Steam Community Market 当前可检索全集为范围，使用 `search/render` 的 `total_count` 与远端分页；本地仅缓存访问页，详情按需加载。
- 理由：不存在普通桌面端可用的正式全市场 Steamworks API；合作伙伴接口需要服务端密钥；全站实测约 52.8 万且每页 10 条，全量扫描约 52,799 请求。
- 影响：G3 新增目录服务、分页缓存和迁移 0006；移除本地标的池/伪全市场涨跌 UI；全量镜像需 Valve 许可后另立变更。
- 关联：docs/research/steam-market-full-market-api-2026-08-13.md、docs/design/steam-full-market-architecture-CR-004.md

### D-018：G3 采用匿名目录会话、用户驱动分页与可恢复增量迁移

- 日期/阶段：2026-08-14 / CR-004 + CR-005 G3
- 决策者：总设计师、后端工程师、数据库工程师、前端工程师
- 背景：全市场浏览需要与登录账户隔离，同时避免内部网页端点被误用为后台全量采集接口。
- 结论：目录请求使用独立匿名网络会话；分页只由用户动作驱动；单品概览按需加载；0006 只做向前兼容增量扩展，回滚通过升级前数据库副本恢复。
- 理由：降低 Cookie 泄漏、限流、条款和破坏旧数据结构的风险，并保持 UI 可解释的来源/时间/缓存状态。
- 影响：G4 必须验证真实 429、结构变化、WebView2 新鲜会话和备份恢复操作；任何持续全量镜像需求必须另立变更并先获 Valve 许可。
- 证据：`docs/implementation/integration-CR-004-CR-005.md`、统一测试、三档视觉冒烟。

### D-019：CR-006 真实走势采用“单品按需 + 来源透明 + 精确语义”

- 日期/阶段：2026-08-17 / CR-006 G1
- 决策者：用户（提出）+ 产品经理 + 总设计师
- 背景：项目已有历史读取与图表基础，但用户要求继续完善并绘制真实数据走向。
- 备选：后台全市场历史采集；第三方历史 API；单品按需读取 Steam 官方市场历史。
- 结论：仅对用户主动打开的单品按需读取并缓存 Steam 官方市场历史；在线/缓存/空数据/失败显式区分；24h 与日 K 按实际历史点粒度命名。
- 理由：在不扩大自动采集与合规风险的前提下交付可追溯真实走势，避免 fixture 或聚合数据被误认作逐笔行情。
- 影响：G2 需冻结历史结果状态和图表契约；G3/4 需完成登录恢复、严格校验、图表重构与真实联网验收。
- 关联：`docs/requirements/PRD-CR-006-real-market-trends.md`。

### D-020：CR-006 采用类型化历史深模块与 v7 来源模型

- 日期/阶段：2026-08-17 / CR-006 G2
- 决策者：系统架构师、数据库工程师、安全工程师、UI/UX 设计师、总设计师
- 背景：现有 `MarketService::detailReady(QVector, QString)` 无法区分在线、缓存、空、认证、限流和 schema 变化；历史表仍有旧三列唯一约束且无来源时间。
- 备选：继续扩展旧信号；WebView DOM 抓图；类型化单品历史深模块。
- 结论：新增 `MarketHistoryService + SteamHistoryParser + PriceHistoryRepository + HistoryDataset`；v7 重建历史表并保存来源/获取时间；图表使用共享时间范围的上下双图。
- 理由：隔离易变网页端点、形成可测试状态契约、修复数据库约束、避免缓存/fixture 冒充在线数据。
- 影响：G3 冻结 API/数据/UI 契约实施；G4 必须完成真实账户联网与脱敏验收。
- 关联：ADR-005、CR-006 架构/API/数据库/安全/UI 文档。
