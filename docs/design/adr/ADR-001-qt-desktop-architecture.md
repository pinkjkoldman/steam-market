# ADR-001：Qt Widgets 单机桌面架构

- 状态：已接受（随 G1+G2 门禁批准生效）
- 日期：2026-08-01 / 阶段 2
- 决策者：系统架构师（用户已确认 Qt 方向）

## 背景

用户确认产品为类似证券软件的行情工具，指定 Qt。需确定 UI 技术（Widgets vs QML）、进程形态（单机 vs 前后端分离）与构建方式。

## 备选方案

1. **A：Qt Widgets 单进程桌面应用**：UI 与服务层同进程，SQLite 本地存储；
2. **B：Qt Quick/QML 桌面应用**：声明式 UI，动画与自定义视觉更强；
3. **C：本地 HTTP 后端 + 前端（Electron/QtWebEngine）**：前后端分离，部署复杂。

## 结论

选择 **A：Qt Widgets 单进程 + 服务层 + SQLite**，构建用 qmake，图表用 Qt Charts。

## 理由

- 行情类界面以表格/列表/图表为主，Widgets 的模型视图（QTableView）性能与定制成本优于 QML；
- 单进程消除前后端通信/部署复杂度，符合"小软件"与单机定位；
- 本机已具备 Qt 6.11 + MinGW 工具链，qmake 可直接构建；
- 通过内部服务契约（OpenAPI 化的接口定义）保持分层边界，未来如需拆分后端无需重写业务逻辑。

## 影响

- 单机单用户，数据本地化，无云同步；
- UI 层通过服务层接口调用，禁止跨层访问网络/数据库；
- Qt Charts 需随发行包可用（见 R-005，回退方案 QCustomPlot）。
