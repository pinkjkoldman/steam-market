# CR-003 决策日志（G2）

日期：2026-08-03

| ID | 决策 | 理由 | 影响 |
|---|---|---|---|
| D-013 | Windows 桌面版采用 WebView2 承载 Steam 官方登录，应用不收集 Steam 密码 | 当前 Qt MinGW 工具链不支持 Qt WebEngine；系统 WebView2 Evergreen 已存在；官方登录可覆盖 Steam Guard | G3 需要引入 WebView2 SDK/Loader 并先做 MinGW 编译探针 |
| D-014 | 自动化边界止于官方 Steam 多项上架页面交接与用户确认 | 降低违反 Steam 自动化条款、会话滥用和不可逆交易风险 | 不实现无人值守 `sellitem`、验证码绕过或自动移动确认 |
| D-015 | 库存默认直接加载并按可交易物品分组，不再要求输入市场名称搜索 | 直接解决卡牌逐个选择的核心场景 | 首屏为库存工作台，搜索只作为本地过滤器 |
| D-016 | 库存以资产层和描述层分离建模，使用 `classid + instanceid` 关联 | Steam 库存返回中资产身份与展示描述分离；同名物品可包含多个 assetid | 支持正确分页、分组、全选与逐资产交接 |
| D-017 | 货币金额统一存储为最小货币单位整数 | 避免浮点误差，便于手续费和上下限校验 | API、数据库、UI 组件都使用 integer minor units |
| D-018 | 同步结果按 `sync_id` 原子切换，失败保留上次成功快照 | 分页中途失败时不得把部分库存展示为完整库存 | 数据库需同步批次、状态和游标字段 |
| D-019 | 对外部 Steam 能力采用适配器边界 | 页面、Cookie、库存响应可能变化 | 登录、库存和交接可以独立替换与测试 |

## 被否决方案

- Qt WebEngine：当前 Qt 6.11 MinGW 构建链不支持。
- 直接采集账号密码并调用旧 RSA 登录接口：安全风险高、对 Steam Guard 和页面变化脆弱。
- 全自动提交市场出售与自动确认：不符合本次合规和安全边界。
- 仅依赖公开库存：无法覆盖私密库存和账号级工作流，可保留为降级能力。
